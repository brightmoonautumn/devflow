# 文件树公共层

文件管理和 Git 提交树共用本目录的展示规则与组件。新增文件树能力时优先扩展此处，再由业务适配层接入，避免复制各页面的递归组件。

- `compactFolders.ts`：唯一的单子目录合并判定。必须只有一个子项且为目录；关闭、截断、重复身份或达到每行 32 段上限时停止。调用方提供身份函数，文件管理使用 Windows 路径规范化，Git 使用仓库内原始路径。保留原始节点引用，不深拷贝业务数据。
- `FileTreeRow.tsx` / `file-tree-row.css`：树行、展开箭头、路径段标签、基础键盘导航及样式。`leading` / `trailing` 接入业务控件，`renderSegment` 支持文件管理的逐段选择、复制与菜单。导航只处理树节点自身的键盘事件，保留内部按钮与复选框的原生操作，并跳过隐藏节点。
- `useCompactFolders.ts`：共用浏览器偏好，沿用 `devflow.explorer.compactFolders` 键；同页面通过事件同步，其他页面通过 storage 事件同步，存储不可用时仍可在当前页面切换。
- `TreeEntryIcon.tsx`：文件类型、目录及根节点图标。

业务适配边界：

- `WorkspaceTree` 负责按需读取、缓存、取消请求、错误重试、工作区修订和权限，以及文件操作。异步读取后调用公共合并判定；根目录独立，保留每个合并路径段的真实路径。
- `GitPanel` 负责将当前可见变更构建成内存树、仓库与 Changes/Unversioned 分组、勾选与半选、Diff 和提交。同步遍历内存节点时调用同一合并判定，不读取磁盘；仓库截断时保留逐层展示。勾选及数量始终来自原始变更文件，目录展开操作记录合并链上每个原始目录的状态。树拓扑仅在状态快照改变时重建。

树展示是 Web 偏好，不增加 HTTP/MCP 接口；业务数据与操作仍由原有核心服务提供。
