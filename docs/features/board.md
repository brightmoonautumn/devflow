# 看板第一版

Codex 本机接入、CLI 命令与日常提示词见 [Codex 看板联动](board-codex.md)。

看板已从浏览器原型改为工作区级本地功能。Web UI 与 MCP 共用 `WorkspaceService::board_read/board_execute`；适配器只负责认证、协议转换与操作者来源。本轮完成源码实现，尚未编译或执行测试，不代表运行验收已经通过。

## 快速记录、AI 整理和 Gitee 同步

- 功能筛选框支持清除并恢复全部功能；选中具体功能后，可从下拉菜单编辑该功能。任务卡片按功能分配不同颜色，未归类使用中性色。

- 流程视图使用轻量分栏、层次化任务卡片和空状态插画；深色主题以状态色点亮卡片边缘，背景使用统一底色，空状态使用提供的图片；列标题下不再显示阶段说明，窄屏继续通过阶段标签切换。任务详情抽屉可通过左侧按钮展开和还原，也支持拖拽或键盘调整宽度；任务描述可一键复制，包括当前尚未保存的编辑内容。人工拖拽可直接调整任务阶段，无须填写说明；移动至待开始或已完成时清除执行者，移动至已完成时清除阻塞，保留已有交付和活动记录。
- 流程视图顶部将功能筛选、快速记录输入框与管理、历史、Gitee 同步、刷新图标放在同一行；快速记录按回车提交，同步状态可通过图标提示查看。任务卡片右键打开操作菜单，选择删除直接执行共享看板事务；任务详情存在未保存修改时阻止删除。

- 任务抽屉顶部用颜色标记展示阶段，悬停显示阶段与执行者，支持键盘聚焦读取说明；移除独占两行的状态属性区。「复制 AI 整理指令」放在任务描述字段标题旁，复用公共 `BaseField.action` 与 `BaseButton`；任务描述默认 12 行并随视口保持至少 260px 的编辑空间，验收缩为 3 行。
- 活动记录默认隐藏，通过抽屉顶部历史按钮展开/收起；展开后滚动到记录区域，重新打开或切换任务时恢复折叠。记录仍仅保存在本地，保存/删除保持底部操作区。此次只进行源码与静态检查，未编译或运行测试。

- 看板表单统一通过公共防腐层使用 `BaseField / BaseInput / BaseTextarea / BaseSelect / BaseCheckbox / BaseButton`。范围包含顶部功能筛选、快速记录、任务抽屉、新建任务、功能编辑、删除迁移、关联起终点、进展/验收说明及 Gitee 设置。未归类的空功能值在 UI 边界映射为不与真实功能 ID 冲突的非空选项，提交核心时仍保持空字符串语义。优先级下拉的字符串回调先校验为「高 / 普通」再更新状态，避免将窄类型状态 setter 直接传给通用字符串回调。
- 看板通用按钮样式用 `:where()` 保持低优先级，避免排除公共控件时意外压过卡片的 `display: block`，造成标题、描述和元信息横向挤压。看板 CSS 仅处理表单布局与业务画布/任务卡片/阶段切换，不覆盖公共控件的边框、主题色、字体、焦点、禁用和展开样式；字段使用 `BaseField` 的标签关联与提示。确认/提示继续使用 `useDialogs`，业务表单沿用原生模态容器，公共下拉层由 `BaseSelect` 自动挂载到对应模态容器。
- 本次组件统一只做源码检查：4 个 TypeScript/TSX 文件的静态语法解析诊断为 0，`git diff --check` 通过；未编译、未执行类型检查或测试，明暗主题、窄屏及下拉交互仍待用户运行验收。

- 流程顶部可只输入标题并回车记录，默认进入待开始。无需先建功能；空字符串 `feature` 表示未归类，支持筛选。描述、验收选填，优先级默认普通；打开任务后直接在详情抽屉修改标题、功能、优先级、描述和验收条件，点击「保存修改」或 Ctrl/Cmd+Enter 保存，不再打开编辑对话框。未保存时暂停后台刷新并保留草稿，保存失败不会清空输入；可撤销修改后关闭。元数据保存使用开始编辑时的看板版本，刷新不会自动授权覆盖并发修改。已有功能和任务不迁移、不重置。
- 任务详情「复制 AI 整理指令」复制当前工作区与任务编号。粘贴到 Codex 后先讨论归类、描述、验收和必要的拆分，确认后通过 MCP 更新原任务。整理元数据无需认领，不会启动 AI、执行代码或改变执行阶段。
- 「Gitee 同步」设置已有仓库的拥有者、仓库路径、已有分支、稳定的看板 UUID；远端固定文件 `boards/<boardId>.json`。建议用独立私有仓库和专用分支。第一版实现自动上传和手动恢复，不自动合并两端编辑，也不映射 Gitee Issues。
- 在启动后端的环境配置 `DEVFLOW_GITEE_TOKEN`，使用有目标仓库读写权限的个人令牌，再启动或重启 DevFlow。前端只显示是否已配置，不接收或回显令牌；配置文件和远端快照不保存令牌。
- 用户保存并启用自动上传后，后端每 30 秒检查**当前活动工作区**。不依赖网页保持打开；只在本地看板版本未同步时上传。失败保留本地数据，下一轮重试；关闭自动上传后仍可手动同步。离开该工作区后暂停检查，重新打开或后端重启后根据持久化版本继续。关闭服务期间不执行同步。
- 同步设置、已同步版本、远端 SHA、最近成功时间和错误保存在对应看板的 `.sync.json`，跨进程操作使用独立操作系统文件锁。界面入口轮询显示待同步、已同步或失败；弹窗展示详情和重试操作。网络请求限定 Gitee HTTPS 地址、禁用重定向并限制超时及响应大小，错误不输出含令牌的请求 URL 或远端响应正文。
- 上传功能、任务、描述、验收、交付、阻塞、布局和关联；移除结构化工作区路径与当前执行者身份。看板及任务的 `activity` 字段均不上传，活动记录仅保留在本地。旧同步配置会触发一次新版快照上传，即使看板业务版本未改变也会从最新文件中移除活动字段（不会改写已有 Git 历史提交）。**正文中用户手动写入的路径或其他信息仍随正文同步**，不做全文内容脱敏。
- 首次绑定发现远端同名文件、远端文件发生改动/删除或其他设备上传后，本机暂停覆盖并提示冲突。恢复时从远端读取并验证快照，使用当前工作区及看板版本提交同一核心事务；恢复前在本地原子保存 `<原看板哈希>.<UUID>.backup.json`。备份失败、快照损坏或版本冲突不会替换本地数据。
- 恢复保留当前工作区身份，沿用本地单调递增版本与任务编号下界；清除执行者，进行中任务回到待开始，待验收及已完成状态保留。恢复不导入远端活动记录，保留本机看板及相同任务编号的已有活动，再追加本机恢复记录。恢复完成后的规范化数据会成为下一次上传内容。另一台电脑先配置相同仓库、分支和看板 UUID，然后主动恢复，不能直接覆盖远端。
- HTTP `POST /api/workspace/board/sync` 和 MCP `board_sync` 共用 `WorkspaceService::board_sync`。请求 `{ workspaceKey, expectedRevision, boardRevision, action, settings? }`；`action` 为 `status/configure/push/restore`，`settings` 为 `{ owner, repo, branch, boardId, automatic }`。MCP 不提供恢复，核心也拒绝 AI 恢复；Web 恢复前弹窗确认。状态操作不要求看板版本相同，配置/推送/恢复需要当前版本。已开始的上传使用当时读取的不可变快照，期间新的本地修改留待下一轮同步。

本轮仅修改源码、补充核心测试代码及静态检查差异；**没有运行编译、构建、类型检查或测试，也没有配置真实 Gitee 凭据或上传真实看板**。Gitee API 联调和运行验收待用户验证。

新增验收项：无功能时快速录入中文待办 → 手动补充描述/归类/验收 → 复制 AI 指令且不改变阶段；开启同步后关闭网页仍上传；断网重试、禁用自动同步、重启继续；双设备冲突不得覆盖；损坏远端、恢复时本地并发修改应拒绝；正常恢复生成备份、清除执行者且保留本机历史；检查远端 JSON 不包含任何 activity 字段。抽屉直接编辑、撤销、Ctrl/Cmd+Enter 保存和并发冲突保留输入需用户运行验收。

界面精简：移除占据整行的底部栏及保存版本文字，“流程 / 架构”切换改为右下角浮动控件；流程列表底部保留滚动留白，避免遮挡最后一个任务，架构画布左下角缩放工具保持独立。“功能关联”入口移入“管理功能”。本轮仅修改源码并检查差异，未编译或运行测试。

## 数据与工作区

- 打开文件夹时以规范化目录为身份；打开 `.code-workspace` 时以工作区文件为身份。未打开工作区时不创建演示看板。
- 持久化位置为 DevFlow 自身 `.devflow/boards/<稳定标识哈希>.json`，与 `recent-workspace.json` 同目录下的 `boards` 文件夹；不会向受管理的 Java / Node 项目自动写配置。
- 文件内同时保留完整 `workspaceKey`，避免哈希碰撞读到其他工作区数据。不同工作区、不同浏览器共用后端保存的数据。
- 工作区“另存为”或从文件夹保存为新的工作区文件会形成新的身份，不会自动合并或搬迁看板。复制/移动 DevFlow 本身时，请同时保留 `.devflow/boards`；可选的 Gitee 快照上传与手动恢复见上节。
- 原子写入使用同目录唯一临时文件、同步文件内容后重命名替换；写入失败清理临时文件，已保存版本保留。损坏文件报错并保留，不回退为空看板、不覆盖原数据。
- 读写必须通过本机认证，并同时校验活动工作区身份和工作区版本。修改额外校验 `boardRevision`。工作区状态锁覆盖完整事务，防止切换期间将写入重定向到另一工作区。
- 每个看板使用操作系统文件锁，覆盖跨进程写入；进程退出后锁自动释放，`.lock` 文件可以持续存在，不代表仍被占用。
- 第一版限制：200 个功能、5000 个任务、1000 条功能关联、8 MiB 数据。每个任务及整个看板各保留最近 1000 条活动记录，时间为 Unix 秒，前端按本地时间展示。

## 功能与任务

- 功能可新建、修改名称/核心描述/目标、调整画布坐标、删除。删除含任务的功能必须显式选择另一个功能迁移任务，关联线同步移除。
- 任务可创建、编辑标题/所属功能/描述/验收条件/优先级、删除。新任务统一进入待开始；编号在同一看板递增，删除后不重复使用。
- 新工作区默认为空。已有浏览器草稿提供主动导入入口，只允许首次使用前导入一次；保留功能、布局、任务正文，清除模拟执行者、状态、交付与旧活动，统一转为待开始。浏览器原草稿不删除。无效草稿不会被替换为演示数据。
- 功能关联支持新增与删除有向关系，禁止自连接、重复及不存在的端点。关系表达结构，不自动形成执行依赖。
- 流程/架构、搜索、任务详情、功能进度共用后端快照；保留窄屏阶段切换。画布拖动时只更新本地预览，放手后提交一次；节点和关联线保持落点预览直到保存响应返回，避免先跳回旧位置再跳到新位置。拖拽、平移及坐标保存期间暂停轮询并取消已发出的背景读取；保存失败回退到已保存坐标并显示错误，手势取消、失去指针捕获或画布卸载后释放交互状态。功能编辑中的坐标提供键盘等价操作。
- 页面空闲时每 5 秒读取变更；编辑表单和拖动任务时暂停刷新。保存失败时保留表单及输入，用户可刷新数据后再决定如何保存，不自动重试覆盖其他入口修改。

## 状态与协作

- 网页支持人工快捷完成：待开始、进行中、待验收均可拖到已完成。抽屉不再展示「标记完成」「标记阻塞」按钮，日常状态调整使用拖拽；保留现有阻塞提示及解除入口。普通任务无需说明或确认；已有其他执行者或阻塞时先确认，并使用确认前的版本提交，拒绝覆盖期间的修改。
- 人工完成由核心 `action.complete` 校验为仅 Web 人工可用，保留任务正文、验收及真实交付，不伪造交付内容；清除执行身份和当前阻塞，追加本地「用户手动标记完成」活动。MCP 不提供该操作，核心也拒绝 AI 绕过验收。AI 继续认领、记录进展、提交待验收。
- 完成后的 6 秒提示提供「撤销」，使用完成后的版本校验并重新打开到待开始；超时后仍可在抽屉重新打开。撤销不会恢复旧执行者或旧阻塞。抽屉移除「认领任务」，「保存修改」「删除」集中在固定底部操作区，保存通过关联表单提交，仍支持必填校验及 Ctrl/Cmd+Enter。
- 已补充核心测试源码，覆盖各未完成阶段的人工完成、AI 拒绝、已有交付保留、阻塞和执行身份清理、重复完成拒绝及重新打开。未运行编译或测试，交互及运行验收待用户验证。

| 操作 | 前置状态 | 结果 / 约束 |
| --- | --- | --- |
| 认领 | 待开始、无阻塞、无执行者 | 进行中，记录执行会话；相同版本的并发认领仅一次成功 |
| 记录进展 | 进行中 | 必填说明，可记录已完成、剩余工作与交接提示 |
| 释放 | 进行中 | 待开始，清除执行者，保留进展历史 |
| 标记 / 解除阻塞 | 未完成 | 认领与提交时检查阻塞，说明必填 |
| 提交验收 | 进行中、无阻塞 | 待验收，交付内容、验证情况及限制由执行者真实填写 |
| 退回修改 | 待验收 | 进行中，必须填写退回原因 |
| 通过验收 | 待验收、无阻塞 | 已完成 |
| 重新打开 | 已完成 | 待开始，清除当前执行者，保留上次交付及历史 |

MCP 会话只能推进、提交、释放或阻塞自己认领的任务，不能修改或删除其他会话已认领的任务。Web 本机用户可以接管或释放中断会话的任务、验收、退回与重开。拖拽调用相同核心状态规则；网页人工可直接标记完成，其他需要说明的操作仍打开输入表单。

执行者不是自动运行引擎：认领不会启动 Codex，不会自动修改代码。用户先在 Codex 中讨论，再要求 Codex 写入、认领和执行；Codex 执行后通过 MCP 记录真实进展及交付。暂停/中断后，可写进展并释放，供新会话认领。Web 的“认领”表示本机用户手工认领，不会显示为 Codex。

本机用户与 MCP 均使用现有本机 owner token。MCP 的 `sessionId` 是协作身份标识，由客户端提供，不是独立认证主体，也不构成恶意客户端之间的安全隔离。第一版不实现多用户角色系统；不在只读分享监听器暴露看板。

## HTTP 与 MCP

- `GET /api/workspace/board?workspaceKey=...&expectedRevision=...` 返回完整快照。
- `POST /api/workspace/board` 接收 `{ workspaceKey, expectedRevision, boardRevision, operation }`，返回保存后的快照。
- MCP `board_get`：参数同 HTTP 读取。先通过 `workspace_get` 获取 `workspaceFile ?? workspaceRoot` 与 `revision`。
- MCP `board_execute`：参数 `{ sessionId, request: { workspaceKey, expectedRevision, boardRevision, operation } }`。同一 Codex 会话必须持续使用稳定且唯一的 `sessionId`（1–200 字节）。
- `operation.type`：`feature_save`、`feature_delete`（含任务时传 `moveTo`）、`edges`、`task_create`、`task_update`、`task_delete`、`action`。Web 另支持首次 `import`。
- `action.action`：MCP 支持 `claim/release/progress/submit/block/unblock`，说明用 `text`；Web 另支持 `approve/reject/reopen/complete`。完整输入字段见 MCP 的 `tools/list` schema；`feature_save` 提交完整功能，`task_update` 提交完整任务元数据。
- 版本冲突返回 `conflict`（HTTP 409），重新读取并评估当前数据后再保存。核心不自动合并过时字段。
- MCP 延续现有 JSON-RPC 基础适配器；完整 MCP 生命周期和传输协议合规仍是现有项目限制，本轮不宣称生产就绪。

MCP 创建任务示例（假定已创建 id 为 `board` 的功能）：

```json
{
  "sessionId": "codex-conversation-unique-id",
  "request": {
    "workspaceKey": "D:/WorkSpace/example.code-workspace",
    "expectedRevision": 3,
    "boardRevision": 1,
    "operation": {
      "type": "task_create",
      "title": "补齐任务保存失败提示",
      "feature": "board",
      "description": "保存失败时保留输入，允许刷新后重新保存。",
      "acceptance": "模拟保存失败后输入不丢失，明确提示尚未保存。",
      "priority": "普通"
    }
  }
}
```

路径和版本须使用实际读取结果，不能照抄示例。
