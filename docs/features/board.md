# 看板第一版

Codex 本机接入、CLI 命令与日常提示词见 [Codex 看板联动](board-codex.md)。

看板已从浏览器原型改为工作区级本地功能。Web UI 与 MCP 共用 `WorkspaceService::board_read/board_execute`；适配器只负责认证、协议转换与操作者来源。本轮完成源码实现，尚未编译或执行测试，不代表运行验收已经通过。

## 数据与工作区

- 打开文件夹时以规范化目录为身份；打开 `.code-workspace` 时以工作区文件为身份。未打开工作区时不创建演示看板。
- 持久化位置为 DevFlow 自身 `.devflow/boards/<稳定标识哈希>.json`，与 `recent-workspace.json` 同目录下的 `boards` 文件夹；不会向受管理的 Java / Node 项目自动写配置。
- 文件内同时保留完整 `workspaceKey`，避免哈希碰撞读到其他工作区数据。不同工作区、不同浏览器共用后端保存的数据。
- 工作区“另存为”或从文件夹保存为新的工作区文件会形成新的身份，第一版不会自动合并或搬迁看板。复制/移动 DevFlow 本身时，请同时保留 `.devflow/boards`；本版没有跨设备同步或自动备份。
- 原子写入使用同目录唯一临时文件、同步文件内容后重命名替换；写入失败清理临时文件，已保存版本保留。损坏文件报错并保留，不回退为空看板、不覆盖原数据。
- 读写必须通过本机认证，并同时校验活动工作区身份和工作区版本。修改额外校验 `boardRevision`。工作区状态锁覆盖完整事务，防止切换期间将写入重定向到另一工作区。
- 每个看板使用操作系统文件锁，覆盖跨进程写入；进程退出后锁自动释放，`.lock` 文件可以持续存在，不代表仍被占用。
- 第一版限制：200 个功能、5000 个任务、1000 条功能关联、8 MiB 数据。每个任务及整个看板各保留最近 1000 条活动记录，时间为 Unix 秒，前端按本地时间展示。

## 功能与任务

- 功能可新建、修改名称/核心描述/目标、调整画布坐标、删除。删除含任务的功能必须显式选择另一个功能迁移任务，关联线同步移除。
- 任务可创建、编辑标题/所属功能/描述/验收条件/优先级、删除。新任务统一进入待开始；编号在同一看板递增，删除后不重复使用。
- 新工作区默认为空。已有浏览器草稿提供主动导入入口，只允许首次使用前导入一次；保留功能、布局、任务正文，清除模拟执行者、状态、交付与旧活动，统一转为待开始。浏览器原草稿不删除。无效草稿不会被替换为演示数据。
- 功能关联支持新增与删除有向关系，禁止自连接、重复及不存在的端点。关系表达结构，不自动形成执行依赖。
- 流程/架构、搜索、任务详情、功能进度共用后端快照；保留窄屏阶段切换。画布拖动时只更新本地预览，放手后提交一次；功能编辑中的坐标提供键盘等价操作。
- 页面空闲时每 5 秒读取变更；编辑表单和拖动任务时暂停刷新。保存失败时保留表单及输入，用户可刷新数据后再决定如何保存，不自动重试覆盖其他入口修改。

## 状态与协作

| 操作 | 前置状态 | 结果 / 约束 |
| --- | --- | --- |
| 认领 | 待开始、无阻塞、无执行者 | 进行中，记录执行会话；相同版本的并发认领仅一次成功 |
| 记录进展 | 进行中 | 必填说明，可记录已完成、剩余工作与交接提示 |
| 释放 | 进行中 | 待开始，清除执行者，保留进展历史 |
| 标记 / 解除阻塞 | 未完成 | 认领与提交时检查阻塞，说明必填 |
| 提交验收 | 进行中、无阻塞 | 待验收，交付内容、验证情况及限制由执行者真实填写 |
| 退回修改 | 待验收 | 进行中，必须填写退回原因 |
| 通过验收 | 待验收、无阻塞 | 已完成 |
| 重新打开 | 已完成 | 待开始，清除当前执行者，保留上次交付及历史 |

MCP 会话只能推进、提交、释放或阻塞自己认领的任务，不能修改或删除其他会话已认领的任务。Web 本机用户可以接管或释放中断会话的任务、验收、退回与重开。拖拽遵守同一套状态规则，不能越过交付与验收；需要说明时打开输入表单。

执行者不是自动运行引擎：认领不会启动 Codex，不会自动修改代码。用户先在 Codex 中讨论，再要求 Codex 写入、认领和执行；Codex 执行后通过 MCP 记录真实进展及交付。暂停/中断后，可写进展并释放，供新会话认领。Web 的“认领”表示本机用户手工认领，不会显示为 Codex。

本机用户与 MCP 均使用现有本机 owner token。MCP 的 `sessionId` 是协作身份标识，由客户端提供，不是独立认证主体，也不构成恶意客户端之间的安全隔离。第一版不实现多用户角色系统；不在只读分享监听器暴露看板。

## HTTP 与 MCP

- `GET /api/workspace/board?workspaceKey=...&expectedRevision=...` 返回完整快照。
- `POST /api/workspace/board` 接收 `{ workspaceKey, expectedRevision, boardRevision, operation }`，返回保存后的快照。
- MCP `board_get`：参数同 HTTP 读取。先通过 `workspace_get` 获取 `workspaceFile ?? workspaceRoot` 与 `revision`。
- MCP `board_execute`：参数 `{ sessionId, request: { workspaceKey, expectedRevision, boardRevision, operation } }`。同一 Codex 会话必须持续使用稳定且唯一的 `sessionId`（1–200 字节）。
- `operation.type`：`feature_save`、`feature_delete`（含任务时传 `moveTo`）、`edges`、`task_create`、`task_update`、`task_delete`、`action`。Web 另支持首次 `import`。
- `action.action`：MCP 支持 `claim/release/progress/submit/block/unblock`，说明用 `text`；Web 另支持 `approve/reject/reopen`。完整输入字段见 MCP 的 `tools/list` schema；`feature_save` 提交完整功能，`task_update` 提交完整任务元数据。
- 版本冲突返回 `conflict`（HTTP 409），重新读取并评估当前数据后再保存。核心不自动合并过时字段。
- MCP 延续现有 JSON-RPC 基础适配器；完整 MCP 生命周期和传输协议合规仍是现有项目限制，本轮不宣称生产就绪。

MCP 创建任务示例（假定已创建 id 为 `board` 的功能）：

```json
{
  "sessionId": "codex-conversation-unique-id",
  "request": {
    "workspaceKey": "D:/WorkSpace/example.code-workspace",
    "expectedRevision": 3,
    "boardRevision": 1,
    "operation": {
      "type": "task_create",
      "title": "补齐任务保存失败提示",
      "feature": "board",
      "description": "保存失败时保留输入，允许刷新后重新保存。",
      "acceptance": "模拟保存失败后输入不丢失，明确提示尚未保存。",
      "priority": "普通"
    }
  }
}
```

路径和版本须使用实际读取结果，不能照抄示例。

## 已确定的产品方向

- 每个工作区独立拥有看板。
- Codex 与用户先讨论，经用户要求后写入功能和任务；上下文保留核心功能描述、任务、目标和关键约定，不重复罗列源码位置。

- 流程与架构使用同一份任务数据。流程为待开始、进行中、待验收、已完成；架构以功能模块为骨架。

## 原型入口与交互

- 左侧活动栏「看板」入口；也可首次以 `/#board` 打开。
- 移除功能地图侧栏及独立顶部工具栏。看板激活时复用应用顶部搜索框搜索任务，服务和任务分别保留搜索词；流程/架构切换位于看板底部面板内。
- 流程：任务搜索、跨列拖拽改变状态，拖动时源卡片淡化、目标列高亮，整列空白区域也可接收任务。窄屏改用阶段切换，拖至阶段标签可切换并放置任务，任务详情提供等价的状态操作。
- 架构：功能模块、关联连线、模块进度和任务摘要；支持平移、缩放、适应画布及拖动模块。连线是演示关系，不支持编辑，筛选后进度按匹配任务计算。
- 详情：查看任务、失焦保存描述及验收条件、切换优先级、解除演示阻塞、模拟认领/释放/交付/退回/通过验收/重新打开。
- 新建：填写标题、所属功能、优先级、核心描述及目标与验收，从各状态列的加号或添加任务入口创建，默认进入对应列。
- 初始任务、执行者、进展和交付结果均为演示内容，不代表真实执行或验证。
- 浏览器 localStorage 以 `devflow.board.prototype.v1:<工作区文件或目录>` 隔离保存任务和布局；无工作区时使用独立的 `demo` 空间。该存储只是原型草稿，不是此前讨论的正式持久化方案。浏览器存储不可用时展示提示。
- 分享只读入口不展示看板；文件工作台保持挂载，切换看板不丢弃未保存编辑。
