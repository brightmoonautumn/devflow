# 看板（前端产品原型）

当前仅实现前端交互，用于确认产品方向。未接入后端、数据库、MCP 或 CLI，也不会调用 Agent、认领真实任务或修改源码。

## 已确定的产品方向

- 每个工作区独立拥有看板。
- Codex 与用户先讨论，经用户要求后写入功能和任务；上下文保留核心功能描述、任务、目标和关键约定，不重复罗列源码位置。
- 按任务认领，允许未来明确授权后连续推进一个功能下的任务。
- 流程与架构使用同一份任务数据。流程为待开始、进行中、待验收、已完成；架构以功能模块为骨架。

## 原型入口与交互

- 左侧活动栏「看板」入口；也可首次以 `/#board` 打开。
- 移除功能地图侧栏及独立顶部工具栏。看板激活时复用应用顶部搜索框搜索任务，服务和任务分别保留搜索词；流程/架构切换位于看板底部面板内。
- 流程：任务搜索、跨列拖拽改变状态，拖动时源卡片淡化、目标列高亮，整列空白区域也可接收任务。窄屏改用阶段切换，拖至阶段标签可切换并放置任务，任务详情提供等价的状态操作。
- 架构：功能模块、关联连线、模块进度和任务摘要；支持平移、缩放、适应画布及拖动模块。连线是演示关系，不支持编辑，筛选后进度按匹配任务计算。
- 详情：查看任务、失焦保存描述及验收条件、切换优先级、解除演示阻塞、模拟认领/释放/交付/退回/通过验收/重新打开。
- 新建：填写标题、所属功能、优先级、核心描述及目标与验收，从各状态列的加号或添加任务入口创建，默认进入对应列。
- 初始任务、执行者、进展和交付结果均为演示内容，不代表真实执行或验证。
- 浏览器 localStorage 以 `devflow.board.prototype.v1:<工作区文件或目录>` 隔离保存任务和布局；无工作区时使用独立的 `demo` 空间。该存储只是原型草稿，不是此前讨论的正式持久化方案。浏览器存储不可用时展示提示。
- 分享只读入口不展示看板；文件工作台保持挂载，切换看板不丢弃未保存编辑。
