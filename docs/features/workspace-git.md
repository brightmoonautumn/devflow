# 工作区 Git 管理

## 范围与交互

左侧活动栏新增 Git 入口。面板参考 IDEA Commit 窗口：上方 `Changes`，下方 `Unversioned Files`，各区按仓库、目录分组，显示分支、数量和状态。两大分组、每个仓库和目录均支持收起/展开，折叠时卸载下层文件节点，切换侧栏及后台刷新保留折叠状态。每个仓库的复选框只选择本仓库文件；子模块有独立仓库分组。

Commit 面板可见且页面可见时，每 5 秒读取核心内存快照；后台更新或快照过期时每秒检查完成状态。快照读取不等于执行 Git 扫描。切回面板或恢复焦点直接复用快照和展开状态，不立即刷新。首次请求最多等待 2 秒后分批展示，尚未读取的仓库只计入统一加载提示，不将其 `blocked` 占位误判为 Merge Conflicts。仅真实冲突文件使用冲突标题；合并/变基进行中、预算等阻塞原因单独显示。手动刷新及添加/回滚/提交结束后的同步强制刷新，最多等待 30 秒，未完成时继续显示同步提示并轮询。操作结束同步前保持忙碌状态；服务端先按涉及仓库失效，普通失效刷新保留 350ms 防抖，5 秒退避只用于读取失败。没有浏览器持久化缓存。

点击文件名或文件复选框都在右侧打开对应只读 Diff，活动文件行高亮；仓库复选框仅控制选择，不批量打开 Diff。文件、目录和仓库图标统一复用公共 `components/files/TreeEntryIcon`，与资源管理器使用相同的类型图标、16px 尺寸、线宽及主题色令牌；文件行字号、29px 行高也保持一致。

- **Add to VCS**：工具栏或文件右键菜单添加所选未管理文件，等同于暂存新增文件；`Unversioned Files` 内的仓库目录和子文件夹也支持右键“添加到 VCS（N 个文件）”。文件夹操作仅传入当前仓库已列出的可选未跟踪文件路径，不传目录 pathspec、不跨子仓库、不包含忽略文件。超过每仓库 500 项时提示分批，不静默截取。添加期间显示进度，结果显示成功文件数或错误，成功后展开 Changes 与对应仓库，并刷新状态以移出 Unversioned Files；用户仍需在 Changes 中勾选提交。资源管理器和 Changes 文件夹没有新增此操作。
- **Rollback**：列出目标文件并确认，将普通已跟踪文件的工作区、暂存区恢复到 HEAD。新增文件只取消暂存，保留磁盘内容；未管理文件不删除。重命名恢复原路径，若原路径已有文件则拒绝覆盖。子模块指针不执行递归回滚或切换子仓库 HEAD。
- **Commit**：勾选文件、填写信息，生成只读预览，点击文件可在右侧 Diff 标签中查看；再次确认才提交。仅提交勾选路径的当前磁盘内容，保留未勾选文件已有的暂存内容。Git hooks、签名和过滤器仍遵循本机 Git 配置；不提供自动 Push、Amend、Shelf、冲突解决或行级提交。
- **Diff**：HEAD 对比工作区磁盘快照；新增/删除文件一侧为空。宽编辑区使用 CodeMirror MergeView 左右对比，小于 680px 使用统一对比。复用现有语言加载和配色；不引入 Monaco。文本规范化 CRLF 为 LF，二进制、非 UTF-8 或任一侧超过 1 MiB 时只展示说明。预览比较的是磁盘内容，Git 过滤器和 hooks 可能影响最终提交对象。

## 提交树紧凑目录与组件复用

- 默认将连续单子目录合并为一行，例如 `src/main/java/ext/plus`；仓库和 Changes/Unversioned 分组独立，文件保持独立，遇到分叉、文件、截断或每行 32 个路径段的上限停止合并。判断依据是当前分组可见的变更文件，不查询真实磁盘兄弟项，不额外触发目录或 Git 扫描。
- 文件管理和 Git 共用 `components/files/compactFolders.ts`、`FileTreeRow.tsx` 及样式：统一合并规则、树行、展开箭头、路径标签和方向键/Home/End/Enter/空格导航。文件管理保留路径段选择、复制与右键操作；Git 通过业务控件保留勾选、半选、变更状态、文件数量和 Diff。
- 两处“紧凑文件夹”按钮共用 `useCompactFolders`，沿用已有浏览器偏好键，同页面即时同步。展开操作以原始目录路径记录整条合并链，关闭紧凑模式后可继续逐层操作；全部展开/折叠仍作用于仓库、分组和目录，后续刷新的新目录继续遵守全局默认状态。
- 树拓扑按仓库变化数组缓存，状态刷新通过字段比较复用未变化的仓库与文件数组，不再对完整快照执行 JSON 序列化比较。折叠分组/仓库/目录时不创建后代 DOM；离开 Git 面板时释放派生目录树和文件 DOM，保留轻量状态、选择、展开位置与提交信息。合并保留原始节点引用，勾选范围、计数、Diff 和提交路径仍使用原始变更文件。此调整属于 Web 展示层，HTTP/MCP 的核心业务服务和权限检查保持共用。
- 本轮仅修改源码和文档并检查差异，未执行编译、类型检查、构建或测试。待人工验收：截图中的长 Java 单路径、单文件目录、目录与文件混排、多分支目录、Changes/Unversioned 与多仓库隔离、父目录勾选和半选、Diff、模式切换、刷新后链条分叉、全部展开/折叠、截断列表、中文及 Windows 路径、明暗主题与 400–550px 分屏、文件管理逐段菜单/复制及两处键盘导航。

## 子模块与多仓库

通过 Git 索引 mode `160000` 发现已初始化子模块，支持嵌套子模块及 `.git` 为文件的情况。父仓库仅显示 `pointerChanged` 的子模块引用更新行；只有子仓库未提交文件变化、HEAD 引用未改变的行不在父仓库展示，也不计入分组数量。子仓库仍独立显示其内部的文件改动，没有可展示变化的仓库分组自动隐藏。子仓库也可以作为显式工作区根目录，按规范路径去重后仍保留父子关系。

1. 子仓库只有未提交文件改动时，不展示父指针行；在子仓库分组查看和提交文件。
2. 提交子仓库仅改变子仓库 HEAD，父仓库不自动提交；刷新后可单独勾选父指针提交。
3. 父指针与对应子仓库文件不能在同一提交计划中出现，防止子仓库提交后父指针与预览不一致。父仓库其他普通文件可以与子仓库文件分别生成提交。
4. 多仓库逐一提交，不是跨仓库事务。前面的成功提交保留；首个提交失败时停止并返回实际结果。先刷新检查结果，再决定后续处理。

子仓库分组显示父仓库名称与悬停路径；父仓库仅展示对应“引用更新”行，提交区不再展示子模块提交顺序提示。复用已有核心提交计划及冲突保护，不增加自动提交父仓库或自动 Push。

### 提交信息表单

Commit Message 区域顶部提供与运行输出相同样式的上下拖拽条，输入框随区域高度伸缩；支持上下方向键微调、Home/End 调到最小/最大高度、双击恢复默认高度，并在当前浏览器记忆高度。可用高度随侧栏布局变化收敛，为文件列表保留空间；小窗口中提交区内容可滚动。此项仅为 Web 布局偏好，无新增 HTTP/MCP 业务接口。本轮未编译或运行测试，待人工验证拖拽、键盘、切换视图、刷新恢复及窄屏布局。

Commit Message 旁提供“规范填写”按钮，打开简化表单：提交类型、影响范围（可选）、简短描述、详细说明（可选）。实时预览 `type(scope): 简短描述`，范围为空时省略括号，详细说明与标题之间保留空行，多行与列表按输入保留。简述不能为空，范围不能包含括号。已有规范消息自动拆分回填；普通消息的首行作为简述，其余内容作为详细说明。已有自定义类型与破坏性变更 `!` 标记继续保留。

“填入提交信息”仅更新原输入框并使旧提交预览失效，仍通过原有预览与确认流程提交；取消或 Escape 不修改原消息。复用公共表单组件，支持明暗主题、窄屏和键盘操作；只读分享不显示入口。此功能仅为前端文本编辑，无新增业务 API，HTTP/MCP 继续接收同一 message 字符串。未编译或运行测试，待用户验证表单回填、取消、已有消息编辑、空范围及多行说明。

未初始化子模块不会自动下载或初始化。detached HEAD、合并/变基/拣选/回退进行中的仓库拒绝提交，冲突文件不能勾选；先使用 Git/IDE 处理。

## 核心与入口

业务位于 `crates/devflow-core/src/workspace/git`，HTTP 与 MCP 使用同一个 WorkspaceService、Git 操作锁和提交计划。适配层只负责鉴权参数、反序列化和结果映射。

| HTTP POST | MCP 工具 | 功能 |
| --- | --- | --- |
| `/api/workspace/git/status` | `workspace_git_status` | 返回仓库、变化和仓库 version |
| `/api/workspace/git/diff` | `workspace_git_diff` | 按仓库 version 和路径读取差异 |
| `/api/workspace/git/mutate` | `workspace_git_mutate` | `add` 或 `rollback`，返回逐仓库结果 |
| `/api/workspace/git/commit/preview` | `workspace_git_commit_preview` | 固定文件快照与提交信息，返回 planId 和 Diff |
| `/api/workspace/git/commit/apply` | `workspace_git_commit_apply` | 校验并消费计划，执行选择提交 |

所有入口需要认证、当前 `expectedRevision`、活动工作区成员资格。文件选择携带 `repository/version/paths`。只授权工作区内的完整仓库根目录，不因打开了仓库中的某个子目录而向上扩大权限。

Git 自动检测已有 PATH 和 Windows 常规安装位置，可通过 `DEVFLOW_GIT_PATH` 指定已有可执行文件绝对路径。找不到时提供安装提示；不自动下载安装 Git。固定参数调用 Git CLI，不通过 shell 拼接。路径使用 NUL 分隔的 literal pathspec，支持中文、空格、通配符字符和以连字符开头的文件名。

## 冲突保护与预算

- 选择提交使用 Git 自身 `commit --only --pathspec-from-file` 临时索引流程，避免将用户未勾选的暂存内容一起提交，也不需要自行交换真实索引。
- 计划 5 分钟有效，内存中只保留最近一个。HEAD、porcelain 状态及文件元数据构成 version，另保存所选磁盘文件的原始字节；提交前再次检查精确字节和工作区 revision。外部 Git 操作或保存导致变化时要求重新预览。Git 与任意外部编辑器之间不存在跨进程文件系统事务。
- Web 在替换/回滚/提交前检查所选文件及重命名前路径的编辑器草稿、保存和读取状态；未完成保存时阻止。回滚后刷新已打开的干净文件标签。MCP 不感知浏览器内存中的草稿，依靠核心磁盘与版本校验。
- 不遍历 `.git/node_modules/target/build/dist`。普通工作区目录发现预算：深度 4、10000 目录项、64 仓库、20 秒；仓库内只通过索引发现子模块。未管理文件由 `ls-files --others --exclude-standard` 配合目录排除获取，提前剪枝依赖/构建目录。
- 仓库变化最多展示 2000 项，不完整或包含不安全路径时禁用该仓库修改。每批最多 32 仓库，每仓库最多 500 个选择，单文件快照最多 4 MiB，提交快照与预览总计最多 16 MiB。符号链接、越界路径、依赖/构建目录禁止操作。
- 每条只读 Git 命令最多 15 秒，修改及 hooks 最多 120 秒，输出最多 16 MiB、错误最多 128 KiB。Windows 隐藏命令窗口；超时复用已有进程身份校验和进程树清理。超时可能发生在 Git 已创建提交后，必须刷新确认，不自动重试提交。

## Diff 滚动与性能优化

- 参考 [VS Code Diff Editor](https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts) 的固定视口布局，以及 [隐藏未变化区域](https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/widget/diffEditor/features/hideUnchangedRegionsFeature.ts) 的交互；实际引擎继续使用现有开源 CodeMirror Merge，未移植 VS Code/Monaco 或增加依赖。
- 按 [MergeView 上游滚动约定](https://github.com/codemirror/merge/blob/main/src/mergeview.ts) 让固定尺寸外层统一负责纵向滚动，内部左右编辑器自然增长，移除原先裁剪内容和固定内部高度的冲突样式。行内视图由自身滚动；窄屏默认行内，支持手动切换左右/行内及上一处/下一处变化，首次打开定位第一处差异。
- 仅在可见尺寸确定后初始化；隐藏标签的零尺寸不再触发布局切换及重建。保留只读选区、行号和键盘导航，移除 basicSetup 的编辑类扩展。长未变化区域折叠但可点击展开；详细差异计算设 100ms/scanLimit 500 预算，超预算回退粗粒度比较，非硬实时保证。总文本大于 300000 字符或存在 20000 字符长行时跳过语法解析，仍展示文本差异。
- 子模块引用采用独立轻量左右视图，显示父仓库原 SHA 与子仓库当前 HEAD SHA，旧/新内容分别使用主题删除/新增底色，完整 SHA 可选择并横向滚动；不为两行引用启动代码编辑器。
- 样式和 CodeMirror API 均封装在公共 `components/editor/GitDiffEditor` 内；文件鉴权、磁盘快照、父子仓库提交计划和 HTTP/MCP 核心逻辑不变。源码与差异空白检查已完成，未编译、运行测试或实机验证。待验收：父仓库隐藏纯 dirty 子模块、仅展示实际引用更新；点击引用展示左右 SHA；大文件滚动、左右对齐、上下差异导航、折叠展开、切换隐藏标签、明暗主题及窄屏。

切回 Commit 的缓存行为已从“过期即在激活/焦点事件中刷新”改为“切换只展示已有视图，独立定时同步”。首次打开没有快照时读取，手动刷新、操作完成后的强制同步以及工作区 revision 变更时的重建继续保留。按约定只检查源码和差异，未编译或运行测试；待验收离开面板后返回、切换浏览器焦点、已有折叠/选择/滚动位置，以及外部 Git 修改经定时同步后正确显示。

## 目录批量选择与全树展开/折叠

- Changes 和 Unversioned Files 中的普通目录新增复选框，选中范围为当前仓库、当前分组下该目录所有层级的可选变更；折叠的后代同样参与。全部选中显示勾选，部分选中显示半选，再次点击全选目录取消其后代选择。冲突/不可选文件不参与，受阻或列表截断仓库和执行操作期间禁用，分享页面继续隐藏所有选择框。目录选择不扫描磁盘、不选择整个仓库、不跨越子仓库边界、不批量打开 Diff。
- Commit 顶部提供“全部展开”和“全部折叠”，统一控制两大分组、仓库及任意层级目录；通过面板受控状态管理，刷新和切换面板保留结果，后续新增目录遵循最近一次全局展开/折叠状态。折叠不清除文件勾选、提交信息或已打开的 Diff。
- 仅修改前端交互，无新增 HTTP/MCP 能力，仍由现有核心校验具体选中路径。未编译或运行测试；待验收嵌套目录全选/半选/取消、折叠后选择、两大分组隔离、不可选文件及只读分享、全部展开/折叠后单独操作和刷新保持。

## 按差异块还原

- 普通文本的左右 Diff 在中间提供向右还原箭头，将对应块从左侧 HEAD 版本恢复到当前工作区；工具栏也可还原通过上一处/下一处定位的当前块，适用于行内视图。文本区域仍不可自由编辑，子模块引用视图与只读分享不提供还原。
- 公共编辑器只计算还原后的文本并回传视图快照，不直接修改只读模型或调用业务 API。业务层先确认回传快照、工作区 revision、已有编辑草稿与保存状态，再读取磁盘；磁盘内容与显示快照一致后，调用既有文件写入服务，以精确 `expectedContent` 防止读取后又发生的外部修改。BOM 和换行延续核心保存规则，不修改 Git 暂存区、HEAD、父子模块引用；已删除文件不通过此入口自动重建。
- 保存成功原位更新 Diff，广播现有文件变更事件，重读干净编辑标签并刷新 Git 状态/提交预览。保存中阻止重复还原，后台状态刷新不绕过核心权限。此能力复用已有 HTTP/MCP 文件读写服务，没有新增业务规则或端点。
- 未编译或运行测试。待验收普通替换/纯新增/纯删除块、末尾有无换行、CRLF/BOM、长文件与行内视图、已打开的脏文件阻止、外部修改冲突、只读文件/分享、已删除文件拒绝重建，以及还原后仍保留其他块和暂存内容。

Git 树默认仅展开 Changes/Unversioned Files 两个分组，仓库与目录默认折叠，普通节点只切换当前层；用户显式点击“全部展开”才递归展示所有层级。文件行补齐与目录箭头等宽的 16px 占位，使同级复选框和图标对齐，子文件相对父目录保持 14px 递进。刷新与切换面板继续保留用户已操作的展开状态。未编译或运行测试；待验收多层目录逐层展开、同级文件/目录对齐及全局展开/折叠。

## Git History

### 入口与交互

Commit 顶部的 History 图标打开独立工具标签页，不占普通文件的 12 标签配额。页面参考 IDEA 的提交图 + 右侧文件/说明结构，使用现有主题与公共 BaseSelect、BaseInput、BaseButton、TreeEntryIcon。宽区域左右布局，小于 700px 改为上下布局，各面板独立滚动。切换标签保留当前历史列表、选中提交、详情与滚动；关闭历史标签、切换工作区 revision 或硬刷新后重新读取，不将 Git 对象写入浏览器持久缓存。

- 首次打开默认聚合全部已发现、已授权的仓库（包含父仓库与已初始化子模块）。仓库筛选支持搜索、多选、全选、清空、仅看某仓库和该仓库及全部子仓库；用户手动选择在 sessionStorage 按工作区保存，仅存筛选偏好。Blame/子模块定位临时聚焦目标仓库，不覆盖手动偏好。
- 聚合列表按各仓库下一条提交的 committer 时间交错展示，保留每个仓库内部的 Git 拓扑顺序；显示仓库短名和稳定色条、主题、作者、时间、HEAD/本地分支/远程跟踪分支/标签。身份与图节点均为“仓库 + SHA”，同 SHA 在不同仓库不合并，也不跨仓库连线。轨道不超过 32 时显示完整图；轨道更多时使用仓库标识总览并提示聚焦查看，550px 以下收起图并采用紧凑换行。每次 50 条，使用核心聚合游标继续，不定时扫描历史。

- 选择提交，右上显示该提交相对父提交的变更文件树，右下显示说明、作者/邮箱、时间、SHA 和引用。合并提交默认对比第一个父提交，可切换直接父提交；根提交对比空树。文件树逐层展开。当前实现不做重命名相似度计算，重命名按删除 + 新增展示。
- 点击历史文件打开共享 Diff 组件，左右标题明确标明父提交和所选提交，标签名称包含短 SHA；同一文件不同提交/父节点使用不同标签键。历史 Diff 读取不可变 Git blobs，工作区未保存或已修改内容不混入；无还原箭头或保存操作。子模块的历史指针复用左右 SHA 视图。

### 核心、接口与权限

核心位于 `crates/devflow-core/src/workspace/git/history.rs`。HTTP 与 MCP 只反序列化和调用相同 WorkspaceService；沿用认证、工作区 revision、规范仓库根目录、文件路径边界、操作锁及受限 Git 进程执行器。所有参数为固定命令和独立参数，提交仅接受完整 40/64 位十六进制 SHA，父节点必须属于该提交的直接父列表，筛选引用必须来自仓库真实 ref。

| HTTP POST | MCP | 内容 |
| --- | --- | --- |
| `/api/workspace/git/history` | `workspace_git_history` | expectedRevision、repository，选填 skip、limit、reference、query、version |
| `/api/workspace/git/history/commit` | `workspace_git_history_commit` | expectedRevision、repository、commit，选填 parent；返回说明和文件 |
| `/api/workspace/git/history/diff` | `workspace_git_history_diff` | expectedRevision、repository、commit、path，选填 parent；返回 historical=true、commit、parent 和现有 Diff 字段 |

分享也通过同一个 App 和核心读取；封闭 ShareReadRequest 新增 `git_history`、`git_history_commit`、`git_history_diff`，不开放修改。邀请目录授权与撤销/过期检查继续生效；分享范围现在也包含授权仓库的历史内容，包括已删除文件的历史版本。

- 每页 1–100 条，默认 50；skip 最大 10000。返回 nextSkip 和全部 refs + HEAD 的版本指纹，继续翻页必须回传 version；读取期间引用变更或后续页使用旧指纹返回冲突，避免重复/跳页。
- 一次详情最多 2000 文件，超过标记 truncated；提交说明超过 256 KiB 截断。每侧 blob 最多 1 MiB，二进制/非 UTF-8/大文件只显示说明。特殊模式、符号链接、排除目录和越界路径不展开。仓库引用筛选最多 4096 项。
- 沿用每命令 15 秒、16 MiB stdout 和 128 KiB stderr 预算及 Windows 进程树超时清理。无 checkout、reset、cherry-pick、历史 revert、远端下载或新的依赖。浅克隆缺失父对象等 Git 错误直接展示，不自动补取。

## Git 扫描与内存缓存

缓存统一位于 devflow-core 的 WorkspaceService，由 HTTP、MCP 和只读分享调用。仓库目录与状态分开：`POST /api/workspace/git/repositories`、MCP `workspace_git_repositories` 只发现仓库并返回已有快照，History 不再为仓库下拉列表触发全工作区状态扫描。status 与 repositories 请求均支持可选 `force`（默认 false），响应新增 `refreshing`、`stale`。分享增加封闭动作 `git_repositories`，旧 `git_status` 请求兼容。

- 仓库目录缓存最多复用 60 秒，目录/index/config/gitmodules 事件使目录缓存失效；发现过程只读取一次 gitlinks，不先扫描状态再重复查子模块。父仓库使用 `--ignore-submodules=dirty`，只显示引用改变，未提交的子模块内容由子仓库自己展示。
- 同仓库同时只安排一个状态任务；共享 4 个后台工作线程、最多 128 个排队任务。展示读取可并行，Git 修改仍通过写锁互斥。后台结果按工作区代次校验，切换工作区后的旧任务不覆盖新缓存。
- notify 8.2 监听文件及 Git 元数据；350 ms 合并事件，读取失败后按 5 秒退避，成功快照失效后不再额外等待 5 秒，60 秒完整校验兜底。普通文件变化只失效最近仓库；子仓库 HEAD/index 等元数据变化同时失效父级引用。文件保存、复制、删除、批量替换及 Git 修改显式失效对应缓存。监听仅标记失效，实际扫描由可见面板请求驱动，隐藏时不定时扫描。
- Windows 使用系统递归通知，无应用层递归遍历依赖目录；事件排除 node_modules/target/build/dist。其他平台注册最多 4096 个经排除规则裁剪的目录。监听失败或达到预算会返回提示，并继续使用低频完整校验。为文件系统通知新增 notify 依赖，不修改用户 Git 配置。
- 历史 blob、提交说明与提交文件列表采用 LRU，最多 512 项、32 MiB 序列化内容；状态列表另有共享 16 MiB 估算预算，超出时截断并禁止基于不完整列表修改。以上预算由本机与各分享入口共用，缓存键与授权范围分别隔离。工作区切换释放原工作区条目；不写磁盘、项目目录、.git 或 localStorage。
- 32 + 16 MiB 是缓存内容预算，并非整个进程的内存上限；结构体、路径元数据、系统监听资源、请求响应复制和 Git 子进程另有开销。授权分享数量仍会影响元数据与监听资源。
- 状态请求判断冷启动时只检查条目是否就绪，不再为此额外克隆一份完整快照。解析仅分配最多 2000 条展示项加 1 条溢出标记，不先创建整份超大文件对象列表；未跟踪命令输出在合并后及时释放，记录解析直接借用 UTF-8 字节。完整状态原始字节仍参与版本计算，超量列表继续标记 truncated 并禁止修改。Git 原始输出缓冲、线程及响应仍有开销，不承诺进程内存立即回落到缓存预算。
- 缓存仅加速展示；Diff、提交预览/执行、回滚和文件保存继续读取真实状态并校验版本。历史缓存命中仍重新检查认证、revision、仓库与路径权限；历史分页的引用指纹仍实时读取。
- 超过 1 秒的发现/状态查询记录耗时便于后续定位；没有未经测量的加速比例承诺。

补充缓存预算、工作区切换、分享键隔离、子仓库事件失效的单测源码，以及默认忽略的临时 Git 仓库场景：目录查询不触发状态、快照复用、外部变更后旧版本 Diff/提交预览拒绝。按用户约定未编译、构建或运行测试；仅检查源码与差异空白。待验收多仓库首次分批显示、再次进入速度、外部修改自动更新、子模块提交后的父引用、监听失败兜底、分享撤销、工作区切换与内存稳定性。

- `POST /api/workspace/git/commit/apply` / MCP `workspace_git_commit_apply` 新增可选 `push`，默认 false，旧请求兼容。核心在创建任何提交前验证所有所选仓库的当前分支和唯一配置上游，缺失上游时不产生本地提交；不自动选择 origin 或创建远端分支。
- 推送由 devflow-core 的同一服务执行，HTTP/MCP 仅适配。每个成功创建的提交使用完整 SHA 和显式上游 refspec，仅推送到已配置远端的一个分支；禁用 force、follow-tags、mirror 和递归子模块推送。发送前再次检查分支、上游和 HEAD；不自动 fetch、merge、修改远端配置或跳过 hooks。
- 返回的各仓库结果新增 `pushed` 和 `pushError`，本地提交失败继续使用原有 `error`。推送失败保留本地提交 SHA 和已提交路径，提示失败原因；面板提供“重试 Push”，只重试已有提交，不再次生成 commit。重试状态仅在当前面板会话保留，重新打开后可使用 Git/IDE 或 MCP 继续推送。
- 独立 `POST /api/workspace/git/push` / MCP `workspace_git_push` 接受 `{ expectedRevision, repository, expectedHead }`。使用相同认证、活动工作区成员与规范路径检查、Git 写锁、HEAD 检查及缓存失效；拒绝合并中仓库。只读分享无提交或推送入口。
- 复用现有 Git 执行器，每次提交/推送命令最多 120 秒，输出有界，Windows 超时清理进程树。前端总请求预算覆盖最多 32 仓库分别提交和推送；超时或连接中断后应重新确认实际远端状态。
- 新增默认忽略的本地临时仓库测试源码，覆盖中文/空格路径、bare 上游正常推送、非快进拒绝后保留本地提交、同 SHA 重试、错误 HEAD、认证/revision、缺失上游阻止提交以及普通 Commit 兼容；MCP 目录与 revision schema 检查同步更新。按约定未编译、构建或执行测试，仅检查源码和差异格式。待验收：删除/选中/明暗主题、双按钮和预览文案、多仓库部分成功、凭证/网络失败、未配置上游、非快进拒绝、重试、子模块独立推送及 Windows 超时清理。


## Update Project 与三栏合并

Git 面板顶部新增下载图标（Update Project），仓库行提供单仓库入口；打开独立的 Update / Merge 工具标签，不占普通文件标签配额。更新页列出各仓库当前分支、已配置的上游、本地阻塞原因和逐仓库结果。默认选择可更新仓库，用户确认范围后逐个执行；遇到冲突或失败暂停剩余仓库，已完成仓库不会回滚。更新前要求暂存区、已跟踪工作区（包含子模块状态）干净；未跟踪文件由 Git 自身检查覆盖风险。无上游、无提交、Detached HEAD、进行中的其他 Git 操作会阻止更新。不自动 Stash、Rebase、Push，不初始化或递归下载子模块。

### 更新任务

核心位于 `crates/devflow-core/src/workspace/git/update.rs`，由 WorkspaceService 同时提供 HTTP/MCP。检查生成包含本地 HEAD、分支、完整已跟踪状态、索引、上游名称及仓库配置的版本；启动必须回传。后台线程执行 Fetch 后再次校验本地版本和工作区 revision，再合并已获取的确定提交。Fetch 仅访问当前分支配置的远端和上游分支；能快进则快进，分叉且无冲突时由 Git 完成合并提交，保留 hooks/签名。获取阶段与合并阶段分别显示，不承诺网络百分比。

进程内同时只允许一个更新任务，保留最近一个任务状态；阶段为 queued/fetching/merging/completed/conflicts/failed。Fetch 上限 180 秒，合并沿用 120 秒，复用现有输出预算和进程树清理；禁止终端提示和 GCM 交互，使用本机已有凭据，认证失败显示 Git 错误。未增加凭据输入表单。关闭/刷新浏览器不取消已经启动的 Git 进程；后台任务可通过 progress 继续查询。服务重启不恢复任务日志，但以 Git 实际 MERGE_HEAD/索引恢复合并现场。超时或传输中断后应刷新确认真实 Git 状态，不能认定工作区没有变化。

### 冲突处理

Git 面板显示 Merge Conflicts 分组。主区域宽屏三栏按“本地当前分支（只读）｜合并结果（可编辑）｜远端上游（只读）”排列；小于 1050px 切换本地/结果/远端面板，支持展开视图，400–550px 将文件列表放在顶部。普通文本的 Base/Local/Incoming 来自 Git 索引 1/2/3 阶段；缺少 Base 的双方新增冲突使用空 Base。中间初始内容为 Git 已自动合并的工作文件，冲突标记用于定位待处理块，支持 merge/diff3/zdiff3 和自定义标记长度。

- 支持上一处/下一处、采用本地块/远端块、按明确顺序保留双方、手动编辑、撤销重做和共同祖先查看。
- 关联滚动按滚动比例同步，不承诺 IDEA 级别的逐行空白补齐；源侧只在选中块能唯一定位时高亮，避免重复代码定位错误。结果区精确标记未解决块。
- 不自动保存合并草稿。点击“保存并标记已解决”或结果区 Ctrl/Cmd+S，才写文件并仅暂存该冲突路径。保存前校验索引、HEAD、MERGE_HEAD 和变更文件快照；出现外部变化时拒绝写入，重新读取需要确认放弃草稿。
- 文本每侧最多 1 MiB，保留工作文件的 UTF-8 BOM 和 LF/CRLF/CR；整文件采用某一侧时使用该侧 Git blob，并保留对应可执行模式。修改/删除冲突可选择缺失一侧来接受删除。
- 二进制、非 UTF-8 或超过 1 MiB 的文件不提供文本编辑；每侧 blob/工作文件不超过 8 MiB 时可整文件选择本地或远端。超过预算、符号链接、子模块指针和复杂目录/重命名冲突引导外部处理。不会用空文本覆盖不支持的对象。
- 单次合并最多 2000 个变更/冲突路径，索引和变更工作文件快照总预算 32 MiB。超过限制要求外部处理；不扫描依赖目录的未跟踪文件。

所有冲突解决并暂存后，可检查提交信息并“完成合并”，提交整个合并索引，与现有部分文件 Commit 分开；存在未暂存修改或冲突时拒绝完成。提供“中止合并”，确认后执行 Git merge --abort，额外的非冲突未暂存修改会阻止中止，不使用 reset --hard；新建的无关未跟踪文件保留。对外部工具开始的合并也可读取现场，但应先检查整个合并暂存区再完成。

更新前检查浏览器中的仓库文件草稿/读取/保存状态；更新期间锁定该仓库普通编辑器并暂停自动保存。工作文件合并期间由核心标记只读，只允许 Merge 专用保存；合并保存仍检查受保护工作区配置、只读权限和规范路径边界。更新结束和保存/完成/中止后刷新文件树、干净文件标签、Git 状态与 History。前端独立轮询任务状态，浏览器刷新后仍能发现进行中的任务；分享页面不显示入口，分享服务不开放以下端点。

## 多仓库历史总览与上游状态

### HTTP / MCP 共用核心

| HTTP POST | MCP | 请求与行为 |
| --- | --- | --- |
| `/api/workspace/git/history/overview` | `workspace_git_history_overview` | expectedRevision，选填 repositories（空/省略为全部已发现仓库）、reference、query、limit、cursor；返回包含 repository 的 commits、nextCursor、references、warnings |
| `/api/workspace/git/sync` | `workspace_git_sync` | expectedRevision，选填 repositories；只比较本机当前分支和上游引用，不扫描工作区、不联网；返回各仓库 branch/upstream/ahead/behind/version/canFetch/reason/lastFetchedAt |
| `/api/workspace/git/fetch` | `workspace_git_fetch` | expectedRevision、repository、version（来自 sync）；只获取当前分支配置的上游；返回新的单仓库 sync 信息 |

核心位于 `git/overview.rs` 和 `git/remote.rs`；旧单仓库 history、详情和 Diff 请求兼容。HTTP/MCP 都只调用 WorkspaceService，不在前端拼接各仓库的分页或计算同步业务规则。

- 总览最多 64 仓库、每页 1–100 条（默认 50）。核心按批次使用最多 4 个有作用域的读线程；复用有界 Git CLI，无新依赖和递归项目扫描。各仓库保持单独 offset 和全 refs/HEAD 版本；游标绑定工作区 revision、规范仓库集合、分支与查询。读取末尾复查每个仓库的版本与授权，任何仓库引用变化都拒绝继续旧分页。
- 每个仓库最多跳过 10000 条；达到边界时停止继续翻页并提示缩小搜索。聚合候选序列化内容预算 32 MiB、游标 32 KiB；每 4 仓库批次之间检查 90 秒预算，单个 Git 只读命令仍最多 15 秒，当前批次须等待其有界命令结束。预算不是硬实时或整个进程 RSS 上限。
- 上游比较使用同一 refs 快照中的完整 SHA 计算 `ahead/behind`，不会把“获取到本机对象库”当成“已合并到本地分支”。页面明确显示“与已知上游一致”“↑ N 待推送”“↓ N 待更新”“↑ N ↓ N 已分叉”“未设置上游/Detached HEAD/状态未知”，颜色仅辅助表达；HEAD、本地和远程标签分别着色。
- `lastFetchedAt` 仅记录当前会话中成功的显式 Fetch 或 Update Project 的 fetch 阶段，不推断其他 Git 工具的成功获取时间；未知时显示“获取时间未知”。记录按工作区缓存代次隔离，配置/目标变化后不套用旧时间，切换工作区或进程重启释放。
- Fetch 要求认证、活动 workspace revision、规范仓库成员、上游检查版本及全局 Git 写锁。目标仅来自已配置远端和唯一上游分支，以显式 refspec 更新 `refs/remotes/*`；允许跟踪远端的强制改写，但不会更新本地分支。使用 atomic、no-tags、no-recurse-submodules，不合并、不 rebase、不 stash、不 push、不改远端配置。复用 120 秒 Git 网络命令超时、输出预算与 Windows 进程树清理。
- 前端按仓库顺序执行 Fetch，显示当前进度，汇总成功和失败，失败仓库不遮蔽已完成的结果；全部结束后重读历史和本地上游状态。关闭/切换工作区会停止后续请求；已经进入核心的单次命令仍由自身超时结束。刷新本地历史和 Fetch 是两个明确的按钮。
- 历史文件中的已初始化、已授权 gitlink 增加“查看子仓库提交”入口，打开指针记录的目标 SHA，不修改子仓库 HEAD；原先的指针 Diff 仍保留。本机尚无该目标对象时提示 Git 读取错误，不自动下载。Blame 定位和页外提交继续按所属仓库正确展示。
- 只读分享增加封闭的 `git_history_overview`、`git_sync` 动作，继续使用邀请的独立工作区范围和撤销/过期检查；不开放 Fetch/Push。分享 read 请求体上限单独增加至 64 KiB 以容纳仓库筛选与游标，其余分享入口仍为 16 KiB。分享的 Fetch 时间与缓存按邀请隔离，未记录时显示未知。

### 验证状态

新增默认忽略的本地 UUID 临时仓库测试源码：相同 SHA 在两个仓库各自出现、连续聚合分页不漏不重且保持仓库内拓扑、跨仓库搜索、筛选/引用变化使游标失效、认证/revision/工作区边界；初始一致、远端前进但未 Fetch 时仍为旧快照、Fetch 后 behind、分叉、远端改写后只更新 tracking ref、HEAD/index/未提交磁盘内容保留、无效版本/目标分支缺失、Detached HEAD、未设置上游、gitlink 跳转不 checkout。同步补充 committer 时间解析、只读协议拒绝 Fetch/Push 与 MCP 工具目录 schema 测试源码。

按项目约定未编译、构建或运行测试，也没有对用户仓库执行 Fetch/Push。仅阅读源码并检查差异格式。待用户编译验收：大量仓库加载与分页、筛选偏好/新仓库加入、相同 SHA 与分支标签颜色、单仓库图/多仓库总览、400–550px 明暗主题、Blame/子模块跳转、Fetch 成功/部分失败/超时、获取时间与上游状态、不改变本地工作区以及邀请只读权限。
