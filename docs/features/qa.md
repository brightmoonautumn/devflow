# QA 质量保证：API 场景测试

## 当前能力

质量保证已从前端示例改为工作区作用域的真实 HTTP 场景执行。Web 与 MCP 共用 `devflow-core::qa`，支持场景配置保存、公共场景引用、独立执行身份、变量提取、RSA 公钥加密、业务断言、异步执行/取消及最近 20 次脱敏记录。没有嵌入 AI 对话或源码编辑器。

入口是左侧「质量保证」。工作区首次使用时点击「初始化 Extreme 200 示例」，只保存配置；选择「系统验收 / 新账号登录并查看个人信息」，填写管理员密码后点击「执行测试」才发送真实请求。页面展示目标环境、账号、运行记录、HTTP 耗时、真实响应与断言；前置以引用按钮展示进度，不重复维护授权步骤。可切换历史记录、场景和视图，运行继续在后端进行。

## 第一个真实环境

- 站点：`http://192.168.1.200/extreme-plus-system-ai/`。
- API：`http://192.168.1.200/prod-api/system/`。
- 验证码由用户关闭；管理员默认 `admin/admin`，密码作为本轮输入传入，不存入场景配置。
- 登录密码按业务前端的 SPKI 公钥做 RSA PKCS#1 v1.5 加密。登录响应 `data` 为 token；授权头直接传 token，不加 Bearer。不同环境/身份可配置授权前缀。
- 基本角色按 `basicRoleCode=cs_role_3035` 查询已有「测试」角色，不固定 Snowflake ID，不分配超级管理员，不改角色已有权限。
- 每轮创建唯一 `qa_df_<随机标识>` 账号，昵称「DevFlow 场景验收」。读取真实开户响应的初始密码（当前系统约定 `user@123456!`），再查询账号 ID、赋予基本角色。
- 新账号独立登录，查询个人信息并断言 ID、用户名与角色；再次使用管理员 token 核对原身份。通过不仅依赖 HTTP 200，还要求 `code=200`、`success=true` 和具体业务字段满足预期。
- 创建的验收账号保留，便于人工核验；不会删除已有数据，不自动回滚或在失败后重放写请求。取消也无法撤销已经发出的请求。

## 公共场景与执行契约

内置定义：`crates/devflow-core/src/qa/extreme.json`，前端不再维护另一套模拟数据。

1. 通用授权 / 管理员登录：输出 `adminToken`。
2. 通用授权 / 开通账号并赋予基本角色：引用管理员登录，输出 `basicRoleId`、`initialPassword`、`accountId`。
3. 系统验收 / 新账号登录并查看个人信息：引用开户场景，输出 `actorAToken`，执行新账号与管理员身份核验。

场景通过 `uses` 引用，按依赖顺序执行，同轮依赖去重；拒绝循环或丢失引用。不同运行变量互相隔离，密码与 token 仅留在工作线程内存中。JSON 请求体支持 `{{variable}}`，独立占位符保留数字/数组等 JSON 类型，路径内变量先编码；从响应通过 JSON Pointer 提取。断言支持 `equals`、`not_equals`、`nonempty`、`contains`。可用 `encrypt` 指定请求体内需要 RSA 加密的 JSON Pointer，不接受脚本或 shell。

## Web 与 MCP

- HTTP `GET /api/qa?workspaceKey=...&expectedRevision=...` / MCP `qa_get`：获取配置、QA revision、运行进度和脱敏历史。
- HTTP `POST /api/qa` / MCP `qa_execute`：`{workspaceKey, expectedRevision, qaRevision, operation}`。
- `operation`：`seed`（仅首次初始化，不覆盖）、`save`（携带 `suite`）、`run`（携带 `scenarioId` 与临时 `inputs`）、`cancel`（携带 `runId`）。
- 示例 run：`{type:"run", scenarioId:"account-profile", inputs:{adminPassword:"由用户提供"}}`。
- 保存与启动要求 workspace revision、QA revision 同时匹配；版本冲突重新读取，不盲目覆盖。每工作区只允许一轮活动执行，Web 与 MCP 共享同一执行锁。配置更新通过 save API/MCP，当前页面暂不提供可视编排编辑。
- 所有操作要求本机所有者认证及活动工作区授权；分享监听器不暴露 QA 入口。

## 边界、持久化与凭证

- 目标 origin 由本机环境变量 `DEVFLOW_QA_ORIGINS` 配置，逗号分隔，默认仅允许本次授权的 `http://192.168.1.200`。相对路径还需位于环境 baseUrl 路径下；禁止完整 URL、跨 origin、上级路径、用户信息和跳转；不使用系统代理，不关闭 TLS 校验。
- 每请求连接 5 秒、总计 20 秒，最多读取 1 MiB JSON；整轮 5 分钟、最多 100 请求、50 场景。展示/持久化的单份请求或响应超过 48 KiB 时保存 24,000 字符脱敏预览并标识截断。
- 凭证字段和已知敏感变量在写盘前脱敏；原始密码、token 不作为输出返回。Snowflake 大整数在报告里转为字符串，防止 JavaScript 精度丢失，实际请求内部保留原类型。自定义业务敏感字段仍需在编排时审查。
- 使用 app 自有 `boards/<工作区哈希>.qa.json`，完整工作区标识防串读；文件锁跨进程互斥，UTF-8 临时文件同步后原子替换。重启后活动记录标记中断，不自动重放请求；历史记录最多 20 条，总存储上限 16 MiB。
- 取消在当前请求结束/超时后生效，不撤销已发生的远端操作。运行固定绑定启动时的配置与工作区，切换页面不启动其他执行。

## 页面交互

- 目录复用 `FileTreeRow`、`TreeEntryIcon` 与资源管理器的整行点击、展开、选中和键盘导航；保留搜索、侧栏边缘收起和拖拽调宽，宽度独立保存。
- 资源管理器、搜索和 QA 共用 240ms 侧栏缓动；拖拽时无过渡延迟，尊重减少动态效果设置。
- 右上角图标切换联动/API/流程视图，不占独立行。结果状态紧邻标题，不使用底部提示栏。
- API 与流程分隔线可拖拽，支持双击默认、方向键、Shift 加速和 Home/End；左右布局流程宽度 25%–65%，默认 35%；窄屏流程高度 180–500px，默认 245px。

## 执行提示与结果回放（2026-10-23）

- 真实请求保持原有速度。执行中按后端 `currentCall` 显示请求中图标，同时高亮 API 与对应行为节点；已完成接口立即显示真实耗时和通过/失败状态。
- 本页观察到新运行完成，且已记录请求耗时总和不超过 5 秒时，自动按真实 `results` 顺序回放，每个请求约 380ms；不会因为轮询、刷新或打开已有历史而反复自动播放。较慢的执行可以手动回放。
- 标题保留后端真实结果，旁边明确显示「结果回放」、步骤名和进度，不将动画当作仍在发送请求。支持「跳过回放」「重新回放」，两者仅修改浏览器展示状态，不调用执行接口。
- 依赖步骤只点亮公共场景引用入口，不自动展开或切换场景。当前业务步骤会在 API 与流程两侧同步高亮，并跟随到可见位置。
- 失败时停在已记录的失败步骤：本场景展开断言；公共前置就地展示失败请求名、错误及断言，可手动打开源场景查看完整证据。不补造未执行步骤。
- 用户滚轮、触摸滚动、拖动滚动条/分隔线、点击步骤或用导航键浏览后，停止自动滚动与选择跟随；回放高亮继续。重新回放重新启用跟随。切换场景/历史记录清理旧回放，配置版本不匹配时禁用回放，避免用新编排解释旧顺序。
- 系统开启减少动态效果时关闭自动/手动定时回放和旋转动画，保留真实结果与即时定位。计时器在跳过、切换及卸载时清理。
- 本轮只修改前端展示与文档，未编译、未运行测试、未重启服务，也未触发新的远端测试请求。待用户验证快速/慢速执行、成功/失败/取消、公共前置失败、历史切换、手动浏览和减少动态效果设置。
