# QA 质量保证：API 场景测试

AI 接口默认返回场景/运行摘要，步骤结果与请求响应单独读取；写操作返回精简版本回执。原 Web 数据契约和完整模式保留，见 [AI 上下文读取](ai-context.md)。

请求 cURL、请求体和响应区域默认展开且可分别折叠，并支持分别复制；JSON 格式化高亮展示且不改变原始数字精度。执行结果直接展示，成功时在标题区域保留绿色「已通过」圆章；本页发起的新运行成功后播放一次快速盖印、回弹与扩散动画，历史记录只显示静态印章，减少动态效果设置下不播放动画；执行记录使用公共下拉组件，不再提供结果回放。

QA 执行状态通过已认证的 SSE 变化通知驱动快照刷新；连接建立和重连时重新读取，执行与取消仍走共享核心。

执行记录切换位于标题右侧，可确认后清除当前列表中的记录；引用执行可能同时出现在其他场景，执行期间不能清除。

场景和文件夹支持删除；会级联删除所有直接或间接引用它们的场景及相关执行记录，确认时展示范围。文件夹是场景分组，远端已执行操作不会撤销。执行期间禁止删除，全部删除后显示空状态。

## 当前能力

质量保证已从前端示例改为工作区作用域的真实 HTTP 场景执行。Web 与 MCP 共用 `devflow-core::qa`，支持场景配置保存、公共场景引用、独立执行身份、变量提取、RSA 公钥加密、业务断言、异步执行/取消及最近 10 次脱敏记录。没有嵌入 AI 对话或源码编辑器。

入口是左侧「质量保证」。工作区首次使用时点击「初始化 Extreme 200 示例」，只保存配置；选择「系统验收 / 新账号登录并查看个人信息」，点击「执行测试」才发送真实请求。页面展示目标环境、账号、运行记录、HTTP 耗时、真实响应与断言；前置以引用按钮展示进度，不重复维护授权步骤。可切换历史记录、场景和视图，运行继续在后端进行。

## 第一个真实环境

- 站点：`http://192.168.1.200/extreme-plus-system-ai/`。
- API：`http://192.168.1.200/prod-api/system/`。
- 验证码由用户关闭；管理员默认 `admin/admin`，密码作为本轮输入传入，不存入场景配置。
- 登录密码按业务前端的 SPKI 公钥做 RSA PKCS#1 v1.5 加密。登录响应 `data` 为 token；授权头直接传 token，不加 Bearer。不同环境/身份可配置授权前缀。
- 基本角色按 `basicRoleCode=cs_role_3035` 查询已有「测试」角色，不固定 Snowflake ID，不分配超级管理员，不改角色已有权限。
- 每轮创建唯一 `qa_df_<随机标识>` 账号，昵称「DevFlow 场景验收」。读取真实开户响应的初始密码（当前系统约定 `user@123456!`），再查询账号 ID、赋予基本角色。
- 新账号独立登录，查询个人信息并断言 ID、用户名与角色；再次使用管理员 token 核对原身份。通过不仅依赖 HTTP 200，还要求 `code=200`、`success=true` 和具体业务字段满足预期。
- 创建的验收账号保留，便于人工核验；不会删除已有数据，不自动回滚或在失败后重放写请求。取消也无法撤销已经发出的请求。

## 管理员登录缓存

Web 在页面内存中缓存管理员 token，按工作区、API 环境、登录定义及登录信息的 SHA-256 摘要隔离；不写入 localStorage 或场景文件，刷新页面后重新登录。相同身份的多次场景执行复用同一个 token；临时测试账号的登录不会混用管理员缓存。

执行时通过临时 `inputs.adminToken` 传入。共享核心在内置 `admin-login-call` 处请求真实 `GET info` 校验；有效则跳过登录，记录实际校验请求与响应。HTTP 401 或业务 code 401（数字或字符串）时执行原登录一次；网络异常、403 和其他业务错误直接记录失败。MCP 也可以传临时 token 使用相同行为。

缓存按每轮执行前校验；执行中若管理员接口返回 401，当前执行保留失败并清除前端缓存，下轮重新登录，不自动重放业务写请求。记录中的 token 仍然脱敏。

## 公共场景与执行契约

内置定义：`crates/devflow-core/src/qa/extreme.json`，前端不再维护另一套模拟数据。

1. 通用授权 / 管理员登录：输出 `adminToken`。
2. 通用授权 / 开通账号并赋予基本角色：引用管理员登录，输出 `basicRoleId`、`initialPassword`、`accountId`。
3. 系统验收 / 新账号登录并查看个人信息：引用开户场景，输出 `actorAToken`，执行新账号与管理员身份核验。

场景通过 `uses` 引用，按依赖顺序执行，同轮依赖去重；拒绝循环或丢失引用。不同运行变量互相隔离，真实请求和原始响应（包含令牌及加密后的请求体）临时保存在服务内存中，供当前工作区查看和复制；服务重启或缓存淘汰后仅保留脱敏记录。JSON 请求体支持 `{{variable}}`，独立占位符保留数字/数组等 JSON 类型，路径内变量先编码；从响应通过 JSON Pointer 提取。断言支持 `equals`、`not_equals`、`nonempty`、`contains`。可用 `encrypt` 指定请求体内需要 RSA 加密的 JSON Pointer，不接受脚本或 shell。

## Web 与 MCP

### 场景清理

行为可配置 `cleanup: true`，同一行为下的请求作为清理步骤。正常步骤按依赖顺序执行；清理在最后执行，场景间按依赖逆序，行为和请求内部保留配置顺序。旧配置默认不含清理，执行方式兼容。

- 成功、接口/断言失败、普通阶段超时及手动取消后都会进入清理；失败后停止剩余普通请求。清理失败仍尝试后续清理请求，不重试。
- 清理行为可配置 `requires: ["adminToken", "testAccountId"]`。每次请求前检查这些变量；缺失、null 或空字符串时记为 `skipped`，不发送请求。仅清理行为允许配置 `requires`。
- 清理有独立的 60 秒预算，仍受单请求 20 秒及整轮 100 请求限制。取消只停止普通步骤，清理期间继续持有工作区执行锁。
- 原始失败保留；清理失败也会使整轮失败，每个清理结果独立记录。页面标明清理行为和跳过结果，HTTP/MCP 共用同一执行逻辑。
- 创建返回成功后应立即提取资源标识或唯一名称，清理只使用本轮变量。创建结果不确定、进程被强制结束或存储不可用时无法保证清理，不自动重放写请求。

例如账号搜索场景中，开户后提取 `searchCreatedUsername`；清理行为先按该用户名读取账号 ID，再由另一个带 `requires: ["adminToken", "searchTestAccountId"]` 的清理行为调用前端同款 `DELETE sys/account/{{searchTestAccountId}}`，最后查询确认已删除。

- HTTP `GET /api/qa?workspaceKey=...&expectedRevision=...` 获取完整配置、QA revision、运行进度和脱敏历史；MCP `qa_get` 默认摘要，通过 read 分别展开场景、步骤和交换详情，full 恢复完整快照。
- HTTP `GET /api/qa/events`：鉴权后订阅当前工作区的变化通知；收到通知后读取快照，重连时重新读取。
- HTTP `POST /api/qa` / MCP `qa_execute`：`{workspaceKey, expectedRevision, qaRevision, operation}`。
- `operation`：`seed`（仅首次初始化，不覆盖）、`save`（携带 `suite`）、`run`（携带 `scenarioId` 与临时 `inputs`）、`cancel`（携带 `runId`）、`clear_history`（携带 `runIds`，永久删除指定已结束记录）。Web 场景库可清空全部记录，文件夹可清空由该文件夹场景发起的记录；被其他场景引用的记录也会一并消失。执行期间不能清空。
- 示例 run：`{type:"run", scenarioId:"account-profile", inputs:{adminPassword:"由用户提供"}}`。
- 保存与启动要求 workspace revision、QA revision 同时匹配；版本冲突时重新读取。每工作区只允许一轮活动执行，Web 与 MCP 共享同一执行锁。Web 支持编辑运行环境和请求响应类型，完整场景定义通过 save API/MCP 保存。
- 所有操作要求本机所有者认证及活动工作区授权；分享监听器不暴露 QA 入口。

## 边界、持久化与凭证

- 本机环境变量 `DEVFLOW_QA_ORIGINS` 可配置逗号分隔的允许来源。未设置时允许 `http://192.168.1.200` 和本机回环地址。相对路径须位于所选环境的基础 URL 路径下。执行器禁止完整 URL、跨来源、上级路径、用户信息和跳转，保持 TLS 校验并直连目标。
- 每个请求连接上限 5 秒。普通 JSON 请求总计 20 秒，SSE 最多 180 秒。两者都最多读取 1 MiB，SSE 也受场景剩余时间和清理预算限制。普通阶段 5 分钟，清理另有 60 秒，编排最多 100 个请求步骤和 50 个场景。持久化的单份请求或响应超过 48 KiB 时保存 24,000 字符脱敏预览。
- 凭证字段和已知敏感变量在写盘前脱敏；执行期间及完成后的最新缓存请求和原始响应会通过已认证的 QA 接口返回；持久化记录仍脱敏。Snowflake 大整数在报告里转为字符串，防止 JavaScript 精度丢失，实际请求内部保留原类型。自定义业务敏感字段仍需在编排时审查。
- 使用 app 自有 `boards/<工作区哈希>.qa.json`，完整工作区标识防串读；文件锁跨进程互斥，UTF-8 临时文件同步后原子替换。重启后活动记录标记中断，不自动重放请求；历史记录最多 10 条，总存储上限 16 MiB。
- 取消在当前请求结束/超时后生效，不撤销已发生的远端操作。运行固定绑定启动时的配置与工作区，切换页面不启动其他执行。

## 页面交互

### 运行环境

在 QA 页面右上角选择运行环境，通过旁边的菜单按钮管理环境名称、基础 URL 和环境变量。变量值按工作区和环境保存在当前浏览器的本地存储中（明文，非密钥库），不会随工作区配置同步；执行时作为本轮 inputs 传入。管理员密码 `adminPassword` 默认使用 `admin`，可在环境管理中为各环境单独修改；其他外部 token 使用对应变量名。环境保存在工作区套件中。整条场景及其前置、清理步骤都使用运行开始时选定的地址，执行记录显示该环境。旧套件直接使用已有的 `name` 和 `baseUrl` 作为默认环境。

同一组场景在不同环境运行时，各环境的基础 URL 应指向对应的服务层级。例如基础 URL 配为 `http://localhost:8081/prod-api/`，请求路径可分别写为 `system/login` 或 `ai/agent/open/shares/…/runs`。已有使用 `login` 相对路径的场景可继续选择指向系统服务的基础 URL。

MCP 保存套件时可提供 `environments: [{id, name, baseUrl}]`。执行时可传 `environmentId`，省略则选第一项或旧套件的默认地址。MCP 调用者仍通过本轮 `inputs` 提供变量和密钥，无法读取浏览器本地变量。执行记录按已有敏感字段规则脱敏，自定义变量名不一定会被识别为敏感信息。

### SSE 请求步骤

展开 API 调用，选择「响应设置 → SSE 流式」，填入结束事件名。MCP 可在请求步骤中保存 `"sse": {"endEvent": "run.completed"}`。请求体依照目标协议配置，例如 Agent 分享请求另需设置 `"stream": true`。

执行器发送 `Accept: text/event-stream`，运行中显示最近收到的事件。收到结束事件后，以其 `data` 解析出的 JSON 做断言和变量提取，再执行下一步。例如可断言 `/status` 为 `SUCCEEDED`，并从 `/runId` 提取运行标识。SSE 要求 HTTP 200，业务字段由场景断言。流提前关闭、结束数据无效或超时会使步骤失败。中间事件保留最多 64 条和 12 KiB 脱敏内容。

- 场景信息区与下方 API/流程区之间的横线支持上下拖拽；信息区缩小时内部滚动，下方保留操作空间。支持双击恢复自动高度、上下方向键微调、Shift 加速及 Home/End。

- 移除流程面板底部的已选择行为与关联接口数量提示。
- API 调用链移除场景输出变量栏，标题右侧提供「展开全部」「收起全部」控制当前场景全部接口详情，单个接口仍可独立展开；手动操作后停止自动定位跟随。

- 目录复用 `FileTreeRow`、`TreeEntryIcon` 与资源管理器的整行点击、展开、选中和键盘导航；保留搜索、侧栏边缘收起和拖拽调宽，宽度独立保存。
- 资源管理器、搜索和 QA 共用 240ms 侧栏缓动；拖拽时无过渡延迟，尊重减少动态效果设置。
- 右上角图标切换联动/API/流程视图，不占独立行。结果状态紧邻标题，不使用底部提示栏。
- API 与流程分隔线可拖拽，支持双击默认、方向键、Shift 加速和 Home/End；左右布局流程宽度 25%–65%，默认 35%；窄屏流程高度 180–500px，默认 245px。

- 真实请求保持原有速度。执行中按后端 `currentCall` 显示请求中图标，同时高亮 API 与对应行为节点；已完成接口立即显示真实耗时和通过/失败状态。
